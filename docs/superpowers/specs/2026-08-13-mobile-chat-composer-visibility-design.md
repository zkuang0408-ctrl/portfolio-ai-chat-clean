# 移动端键盘展开时输入区可见性设计

## 目标

手机输入法弹出并缩短问答框可用高度后，确保“继续提问、输入框、发送按钮和提示文字”完整显示在键盘上方，不再被遮挡约四分之一。

## 已确认方案

采用内部滚动校正方案：

- 保持问答框外框当前的顶部、键盘贴边位置和四角 `24px` 圆角不变。
- 输入框聚焦期间，当 Visual Viewport 的高度或偏移发生变化时，将问答框内部平滑校正到能完整显示输入区的位置。
- 校正目标以输入区和提示文字的下边界为准，并保留少量框内底部呼吸空间。
- 不在普通页面滚动或用户主动查看历史回答时持续强制滚到底；只响应键盘几何变化以及首次聚焦后的稳定帧。
- 键盘收起后不改变页面主体滚动位置，继续沿用现有恢复逻辑。

## 实现边界

- 优先复用现有 `.chat-panel.chat-scroll-region` 单滚动容器，不新增嵌套滚动区域。
- 通过现有聊天展示控制器处理聚焦和 Visual Viewport 事件，不依赖固定键盘高度。
- 不固定 composer，不遮挡回答内容，不改变发送、加载、来源或推荐问题逻辑。
- 仅影响 `max-width: 760px` 的移动端；桌面端、首页布局和 Production 不变。

## 验收标准

1. 键盘完全展开后，输入框、发送按钮与状态提示全部位于可视键盘边界上方。
2. 问答框外框仍与键盘边界贴合，四角保持 `24px`。
3. 320px、390px、430px 和横屏移动视口中输入区无裁切。
4. 119px 到 120px 键盘激活阈值附近不闪烁、不跳动。
5. 用户主动向上滚动阅读后，不因普通页面事件被持续拉回底部。
6. 桌面端行为和布局不变。

## 验证

- 先添加失败的控制器单元测试和移动端 Playwright 可见性断言。
- 实现最小滚动校正后运行相关测试、完整 Vitest、生产构建和四种移动视口验证。
- 只部署 Cloudflare Preview，等待验收后再决定 Production。
